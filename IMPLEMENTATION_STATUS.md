## Runtime decisions

One web and one worker remain the deployment boundary. The worker polls five due sources every 15 minutes, uses bounded GitHub pages (20 items/page, five pages; recent 100 coverage), preserves older history and reports limited coverage. This reduces oversized release payloads while retaining canonical upstream links. Runtime GitHub requests are anonymous/conditional; the catalog bootstrap may use the job's ephemeral token, which is not stored in Fly.

Worker health requires a completed durable tick within 35 minutes. Fly liveness does not query Neon. Daily reporting bootstraps 105 complete UTC dates then refreshes 45; 30-day engaged retention observes authenticated activity on days 23–37 and is mature after 37 days. Subscription retention remains separately reported. Missing coverage is unavailable, never fabricated zero. Mock delivery never contributes to actual email delivery rates or blocks later real receipts. Processed webhooks/auth acknowledgements and completed digest payloads have bounded retention; retry/ambiguous work remains available for reconciliation.

Web, worker and reporting use separate SQL roles. The aggregate role sees only precomputed reporting cells and is transaction-read-only. Fly secrets are app-wide: SQL clients are scoped, but this single-app deployment does not provide OS-level secret separation. Production AI uses only the fixed small-cell-suppressed aggregate HTTP endpoint, never raw subscriber SQL. Its token was stored directly in protected GitHub secrets and locally encrypted with Windows DPAPI, without entering chat or tracked files.
