## Runtime and measurement boundaries

Worker opt-in is WORKER_ENABLED=true with catalog-poll or mock-pilot mode, reviewed DATABASE_URL and CATALOG_GIT_SHA. Mock-pilot also requires canonical HTTPS APP_URL, UNSUBSCRIBE_SECRET of at least 32 bytes, SENDER_IDENTITY and SENDER_CONTACT. Public email must remain false and delivery mode mock. It never applies migrations automatically. Catalog/polling uses row locks/SKIP LOCKED, five-minute-to-six-hour exponential failure backoff and explicit historyLimited/source status for recent-500 coverage. Daily reports refresh 45 complete UTC dates. Health remains preview/mock with workerReady:false.

The durable queue persists immutable payload/items, reserves queued releases and uses fenced lease claims. Acceptance rechecks consent, suppression, monitors and deletion, and only accepted sends create receipts. Normal backlog is not silently capped at 30 days; bounded overflow is retried after one minute. Cancellation after firstAttemptAt is quarantined failed, avoiding blind repeat sends. Old ambiguous/exhausted attempts require reconciliation. The runtime uses only MockEmailGateway; its inbox is process-local and is not a durable provider. A separate Resend SDK adapter is implemented/tested with injected transport and native timeout, but remains dormant behind sender/owner/domain gates. No real SDK send occurred.
Historical snapshots serialize account mutations and suppression by user row lock. Activation uses simultaneous three-monitor state in the first seven days of a matured verified cohort; retention uses the state at day 30. Cohorts without an authoritative baseline are explicitly unmeasured. Aggregate readers query only the aggregate table, suppress counts below ten, reject arbitrary parameters/SQL and require independent bearer authorization. Admin UI additionally requires an authenticated admin role. Production database role isolation, scalable query optimization, retention jobs and distributed rate limits remain open.

Webhook verification uses the Resend SDK against the raw bounded body and Svix signature/timestamp headers. Provider event IDs dedupe transactionally; tracking-off events cannot populate open/click metrics; bounce/complaint suppresses future sends and cancels pending/claimed jobs. Unmatched message IDs retry safely rather than discarding acknowledgement races; authentication-message correlation and retry-exhaustion reconciliation are not implemented. No live endpoint registration is claimed.
